Workflow

Build, select, propose, accept, rebuild, publish. The canvas never silently pushes or switches branches.

Generated clauses and tables are read-only: their source map identifies the manifest, profiles or model owner.

Private content stays local except for your existing Copilot session and explicit GitHub actions. Preview scripts and remote images are blocked.

Workflow guide

Select, ask or edit, review, accept locally, then publish. Questions and staged proposals do not change source files. Only acceptance writes locally; publishing and posting comments require separate confirmation.

Read and select content
  1. Choose a Specification and click Build preview. The initial specification builds automatically on open.
  2. Use the document contents or Find next to navigate. The preview always uses a light theme, including tables and code blocks, regardless of the app or OS theme.
  3. Drag the divider between the preview and review sidebar left to enlarge the editing panel, or right to enlarge the preview. You can also focus the divider and use the arrow keys. On narrow windows the panels stack instead.
  4. Highlight text within one clause, table or figure, or click its source pencil to select the mapped block. The Edit tab shows its file, lines and Markdown.
  5. Check whether the editor says exact selection or mapped block. Formatted or ambiguous text may select the whole block; changes must preserve the surrounding Markdown.

Rebuilds, accepting edits and undo retain the reading position where possible. Generated clauses, node tables and agreement text are read-only; their owning source is shown. Figures are displayed here, not edited as drawings.

Ask questions, then request changes
  1. Select content and enter a question in Edit. Explain or What is this? fills in a prompt; then click Ask about selection.
  2. Read the answer in Drafts. Asking does not rewrite anything, and questions also work for generated content.
  3. Under the answer, enter another question and choose Ask follow-up, or describe a desired change and choose Request change from answer.
  4. A change request includes the selection and discussion history, but still returns a proposal for you to review and accept. Generated content cannot be converted to a Markdown edit here.

Copilot requests may wait until the current session turn ends. Cancel question discards a queued answer. If the source changed since the question, rebuild and select the current text again.

Edit manually or with Copilot
  1. Select authored content. For a manual edit, change the Markdown source and click Stage manual draft. For an assisted edit, describe the change and click Request rewrite.
  2. Use Insert cross-reference to insert a source anchor at the Markdown cursor; it becomes part of the manual draft.
  3. In Drafts, inspect the before/after diff and Full replacement Markdown. Choose Accept locally to write and rebuild, or Reject to discard without writing.
  4. Use Undo accepted edit to restore the last canvas edit if no later external changes would be overwritten. Undo does not rewrite Git history.

Stage text before closing: unsaved textarea contents are transient. Staged drafts, answers and undo snapshots persist. A stale draft is refused rather than overwriting newer source; rebuild and create a fresh selection.

Read and post PR comments
  1. Open PR comments and click Refresh to read the open PR for this branch.
  2. Use Go to source on a current thread to select its mapped content and prepare an instruction to address it. Enter the instruction and request a rewrite separately.
  3. Choose Reply on a thread, or select General PR comment or Inline on selected source line. Write the comment, click Post to GitHub..., and confirm.

Inline comments require a changed PR line, local HEAD matching the PR head, and no local edits in that file. Publish or sync first, or deliberately choose a general comment. Outdated, deletion-side or locally diverged threads stay in the sidebar without misleading pins. Resolved-thread status is not displayed.

Publish accepted edits to a PR
  1. Accept or reject pending drafts, and ensure the accepted source has a successful current preview.
  2. Click Publish to PR... and confirm. This authorizes Copilot to validate, commit and push accepted source changes on this feature branch.
  3. Copilot updates the branch's existing PR, or creates one using the repository's PR template. Review any approval or blocker in the session; the outcome appears in Drafts.

Opening, asking, staging and accepting do not push anything. Unrelated edits require separate approval. Generated output is not automatically staged, and this flow does not merge the PR.

Open another repository or PR
  1. In Tools, enter owner/repository or a GitHub PR URL.
  2. Click Open in separate session. Copilot opens an isolated session for that target and this user-scoped canvas there.
  3. Follow the session link or resolve any blocker reported in Drafts and the Copilot conversation.

The current checkout is not switched. Each repository needs the supported OPC publisher pipeline, its .NET SDK and restored pinned tools. GitHub operations use your own authenticated gh CLI.

Troubleshooting and privacy

Build failed: read Tools / Publisher diagnostics, fix the reported source or dependency problem, and rebuild. Missing pinned tools can be restored with dotnet tool restore in the intended checkout. A failed build does not make an old preview safe to edit.

Request queued: let Copilot finish the current turn and check the session for permission prompts. Failed requests report their error; they are not silently retried.

Source changed: rebuild, reselect and restage. Hash checks protect external edits from stale proposals and undo.

No PR: accept a source edit, rebuild, and explicitly publish. Merely opening the canvas does not create a PR.

Review data is stored locally under the installed extension's artifacts/ directory, keyed by checkout and branch. Do not include that directory when sharing the extension. Selected content is sent to your existing Copilot session; confirmed comments and publishing go to GitHub. The preview blocks scripts and remote images.
