# Word choice

Choose the plainest word that carries the exact meaning, then use it the same
way every time. For individual words, look them up in [term-list.md](term-list.md)
and [term-collections.md](term-collections.md).

## Simple words

Use short, common words. Readers scan, and many read in a second language or
through machine translation.

| Instead of | Use |
|---|---|
| utilize, leverage | use |
| extract | remove, get |
| inform | tell |
| in order to | to |
| in addition | also |
| establish connectivity | connect |
| attempt to | try |
| commence, initiate | start, begin |
| terminate | end, stop |
| facilitate | help, make possible |
| prior to | before |
| a number of | some, several, or the exact number |
| at this point in time | now |
| is able to | can |

- Replace weak verbs (*be*, *have*, *make*, *do*, *perform*, *provide*) with a
  verb that names the action.
- Cut intensifiers and filler adverbs: *very*, *quite*, *really*, *simply*,
  *just*, *easily*, *quickly*, *effectively*. If something is fast, give the
  number.
- Avoid *simple*, *easy*, and *obviously*. What's easy for the writer can be
  hard for the reader.

## One meaning per word, one word per meaning

- Use a word that has one clear meaning in context. Write *because* for cause,
  not *since* (time) or *as* (comparison).
- Pick one term for each concept and keep it. Don't alternate *endpoint*,
  *address*, and *URL* for the same thing.
- Watch words that are both nouns and verbs: *file*, *post*, *mark*, *screen*,
  *record*, *report*, *list*, *map*, *flag*. Make the part of speech obvious.
- Don't use a verb as a noun or a noun as a verb: *request*, not *ask* (noun);
  *affect*, not *impact* (verb); *invitation*, not *invite* (noun).
- Don't coin words (*bucketize*, *configurability*) or give ordinary words new
  meanings (*graveyard* for archive).
- Don't attribute human feelings or intent to software or devices. *The service
  rejects the token*, not *the service doesn't like the token*.

## Technical terms

- Prefer a common word when it says the same thing: *copy*, not *rip*.
- Use a technical term when the audience expects it and it's more precise. Use
  the term as the industry uses it, verified against authoritative sources such
  as standards, specifications, and technical journals.
- Define a term in context the first time it appears, and use it consistently
  afterward.
- Don't invent a term when an established one exists. Before adopting an
  emerging term, check how the field uses it.
- When a common word has a specialized meaning in your field, define that
  meaning.

## Jargon

Jargon is a technical term used where a plain one would do, or a term the
audience doesn't share. Tests:

- If you suspect a word is jargon, it probably is.
- Acronyms and abbreviations are often jargon.
- If a reviewer flags a term, treat it as jargon.
- If the general press uses a term without explanation, most audiences know it.
- If technical journals use a term without explanation, technical audiences
  know it.

Prefer the familiar word: *symbol*, not *glyph*, for general readers. Avoid
business and marketing jargon outright: *leverage*, *synergy*, *empower*,
*best-of-breed*, *robust* (as praise), *seamless*, *world-class*.

## Acronyms and abbreviations

- Spell out a term on first use and follow it with the acronym in parentheses:
  *message authentication code (MAC)*. After that, use the acronym.
- Skip the spelled-out form when the acronym is better known than the term
  (*URL*, *USB*, *PDF*, *HTML*) or the audience certainly knows it.
- Don't introduce an acronym you use only once. Spell out the term instead.
- Don't introduce an acronym in a heading or title. Introduce it in the first
  body text that follows.
- Lowercase the spelled-out form unless it's a proper noun. Names of protocols,
  standards, and specifications are often proper nouns.
- Choose *a* or *an* by pronunciation: *an HTTP request*, *a SQL query*, *an
  SDK*.
- Form the plural with a lowercase *s*: *APIs*, *URIs*.
- Avoid possessive acronyms unless the acronym names an organization or person.
- Spell out an acronym again in a long document when readers might arrive at a
  later section first.
- Avoid acronyms that also spell an English word when the text will be machine
  translated.

## Latin and non-English words

Write the English phrase.

| Instead of | Use |
|---|---|
| e.g. | for example |
| i.e. | that is |
| etc. | and so on, or list the items (keep *etc.* only where space is tight) |
| via | through, by using, with |
| vs. (in prose) | compared to, or |
| per | for each, according to |
| de facto, ad hoc, a priori | in practice, as needed, beforehand |
| viz., ergo, cf. | namely, therefore, compare |

Use US spelling consistently.

## Contractions

- Use common contractions: *it's*, *you're*, *don't*, *isn't*, *can't*,
  *we'll*.
- Don't form contractions from a noun and a verb: *the service is*, not *the
  service's* (for *is*).
- Avoid ambiguous or awkward ones: *there'd*, *it'll*, *they'd*, *should've*.
- Don't mix the contracted and full forms of the same phrase in one document,
  except for deliberate emphasis: *Do not delete this key.*
