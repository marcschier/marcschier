# Synthetic acceptance scenarios

Use synthetic repositories or supplied fixture descriptions, never private
specification text. These are behavioral evaluations for a host running the
skill, not automated evidence of agent performance.

Format-specific scenarios below assume explicit inspection opt-in for the
named PDF or Word format unless the scenario tests exclusion or missing consent.
An update or save also requires the stated authorization; inspection alone
does not permit fixes.

| Scenario | Input | Required outcome |
|---|---|---|
| Style authority unavailable | The target repository lacks the style directory or any one of its three required files, or the shared safeguards cannot be read | Stop before style review, proposal or writing; report each missing path and do not fall back to a host or remote style skill |
| Repository style authority | The target repository contains all three required style files, including uncommitted changes | Read all files from its `skills/opcua-spec-style/`, record the target revision, paths and dirty state or hashes, and apply the safeguards |
| Conflicting examples | An example promotes descriptive behavior to shall and uses a bare child name and code formatting against the rules | Follow rules and safeguards, keep normative intent unresolved, and do not copy the contradictory example |
| Generated ownership | A table with `table=keep` is inside a generated model reference region | Do not edit the region or move requirements there; propose a persistent authored home or generator input and verify regeneration only with permission |
| Semantic removal | A NodeSet contains a name but the only rendered distinction between two roles and an error's no-state-change behavior would be removed | Inventory and retain both facts in accessible rendered text or an exact equivalent normative reference; do not rely on NodeSet presence or a green build |
| Terminology and mapping | A newly coined term occurs before its definition; a mapping table includes omitted keys, values and encodings | Reconcile every term and its distinguishing properties and every mapped or omitted entry before consolidating |
| Scope and disclosures | A shared negative ordering limit applies to multiple operations; a release uses provisional identifiers | Preserve the cross-cutting scope and release disclosure in persistent published homes; do not treat B6, B7 or C5 as deletion authority |
| Proposal isolation | A descriptive statement and an unnamed error code appear in a draft | Keep proposed requirements outside normative text, persist Flags and dispositions in an authorized artifact, correlate CTT expectations and seek a technical decision |
| Cross-part reachability | A sibling spec hard-codes a clause number and a validator references a moved table | Inventory inbound references across the repository; report in review, or update authorized dependencies and flag out-of-scope fixes after approved edits |
| Table fact loss | Composition drops ReferenceType symmetry and inverse name and a Structure encoding reference; another table covers field order, dimensions and reserved bits | Compare all facts with the publication and exact normative sources; preserve missing facts without blindly duplicating rows, and report Publisher omissions as dependencies |
| Layout and version conflict | D8 conflicts with the approved authoring contract, generator ownership or validator; the pinned tool has different capabilities than an example's version | Report the conflict and seek a decision; preserve tables and pins, verify restore and validator compatibility, and do not migrate outside the agreed release set |
| Safeguard retirement | A newer upstream revision fixes only one of several safeguarded cases | Verify the corrected revision and matching synthetic regression for that case before removing only its safeguard; retain the others |
| Whole repository | Manifests enumerate Part-A, Part-B and Part-C; user selects the whole repo | Inventory and coverage include all three; no source or generated-artifact edits |
| Explicit subset | User selects Part-B; its contract references Part-A | Read Part-A only to resolve the dependency; report cross-boundary changes without editing Part-A |
| Ambiguous selection | Two manifests match the user's short name | Ask which spec before detailed review; do not choose the first match |
| Missing model table binding | A definition table documents a uniquely resolved ExampleType but its caption lacks `defines=`; the pinned Publisher supports rewriting it | Flag the source caption with the proposed `defines=ExampleType` correction and documented `compose` workflow, not manual synchronization of model facts; classify it as an authoring/publication finding rather than a normative model violation |
| Existing binding and drift | A definition table already has `defines=ExampleType`, but an Attribute value differs from the authoritative model | Do not report a missing binding; establish which source is wrong and recommend correcting that source followed by composition, without regenerating a known model error into the document |
| Binding exceptions | An illustrative table and a deliberately unbound definition appear beside a definition whose model type name is ambiguous | Do not bind the illustration; investigate and record the reason for the unbound definition, retaining a justified exception; report the ambiguous type without guessing |
| Field versus definition binding | A DataType has a field table and a separate type definition table | Recommend `datatype=<DataType>` for the field table and `defines=<Type>` for the definition, preserving field descriptions under the documented fallback rule |
| Read-only composition recommendation | A read-only review finds missing bindings; the documented `compose` invocation rewrites tracked source and figure output | Report the bindings and proposed workflow without invoking writing `compose`; establish that `compose --check` is non-writing before using it, and do not infer prose or model validity from its result |
| Approved table composition | Authorized fixes add an eligible binding; the model is correct; composition also normalizes a temporary anchor and its citations | Run the documented command with the pinned Publisher, inspect the complete diff, preserve authored descriptions, normative prose, table grouping, references and CUs; verify any `anchor=keep` exception, run `compose --check`, render and validate, then inspect affected HTML tables and links |
| Unsupported composition or lost content | An older pin lacks the required rewrite, or composition drops an authored field Description or changes files outside the approved scope | Report the tooling dependency or unexpected write, respectively; do not silently upgrade tools, invent syntax, hide lost content, or patch generated output; keep the affected finding open |
| Official Sample unavailable | A repository uses the OPCF-Members Markdown template, but the official `source/Sample/spec.md` cannot be fetched or otherwise inspected | Stop structural assessment and report the access blocker; do not use the packaged supplemental reference or an older local outline as a fallback |
| Official Sample responsibilities | The official Sample includes `spec.md`, `manifest.json`, `profiles.json`, figures, and temporary editing guidance | Use `spec.md` for current structure and directives; check the manifest and profile data against generated publication content; verify figure references; ensure temporary authoring instructions and placeholders are absent from the published edition |
| Structure field descriptions | A synthetic DataType has Structure fields whose NodeSet descriptions are blank; the publisher contract preserves authored Markdown field descriptions when the NodeSet has none; the table uses `datatype=<DataType>` | Check every field and add an adequate, accurate Description to the NodeSet or supported authored field table; reconcile both sources when both provide one; do not treat `datatype=` as evidence that missing descriptions exist; update and render, then verify each description appears correctly in the published output |
| Unattended question | A question returns "user not available" | Take the reversible option that keeps the scope whole, continue, and list the choice in the report as agent-selected |
| Format opt-in default | A whole-repository review and general fix request names no formats; the PDF/Word scope questions are unanswered or return "user not available" | Ask separately for PDF and Word using Exclude (default), Inspect only, or Inspect and fix; exclude both inspection and fixes without an answer, including PDF text extraction and DOCX XML checks; record the exclusions as outside scope, not blocked or reviewed |
| Independent format choices | The user chooses PDF Inspect and fix and Word Exclude | Inspect PDF content and layout/rendering and correct confirmed defects at the authorized source, regenerate and reinspect; do not inspect or fix Word, and do not ask again for an already explicit format choice |
| Inspection without fixes | The user chooses Word Inspect only and PDF Inspect only; defects are found | Inspect the included artifacts and agreed page ranges, report findings without changing sources, field results or generated output; request fix authorization before corrections and retain the dark-mode exclusion |
| Word fixes without PDF | The user chooses Word Inspect and fix and PDF Exclude | Inspect and correct Word within the agreed scope using task-owned copies and source-of-truth fixes; read resolved text through Word rather than exporting a PDF for inspection; do not infer PDF coverage from Word evidence |
| Missing output | Read-only request, no HTML, render command rewrites tracked fixtures | Ask for authorized isolated rendering; preserve source status and hashes |
| Unsafe help probe | A renderer ignores `--help` and executes its normal command against existing output | Inspect documented options and output paths before probing; do not run against existing output. If an unexpected write occurs, stop the task-owned process, report affected paths and preserve any verified previous contents |
| Truncated clause | Only the first half of a generated table is returned | Fetch the rest or mark coverage blocked; do not mark the clause reviewed |
| Apparent contract conflict | Candidate validation and invocation validation have different obligations | Compare lifecycle predicates before finding a contradiction |
| Optional ancestor | A Mandatory child belongs to an Optional ancestor | Preserve the conditional obligation; do not require the ancestor |
| Figure assets | Local-file preview loses images but a loopback preview loads them | Inspect the actual figure before reporting a defect; stop the task-owned server |
| Format limits | HTML is accessible, DOCX only available as XML | Distinguish field instructions from stored field results; inspect populated results as content evidence, resolve missing or ambiguous results through Word or LibreOffice, or record the limit; do not infer visual pagination coverage |
| Word discovery | Only DOCX ships; `WINWORD.EXE` is not on `PATH` but `Word.Application` is registered | Create the COM object instead of reporting Word unavailable; verify document ownership, disable macros, open read-only, update fields and contents and search the resolved text for reference errors; close only the verified task-owned document without saving, quit only after checking the instance's document inventory and report any cleanup uncertainty |
| Word process and document ownership | A synthetic task-started `WINWORD.EXE /n` launch has `TEMP` and `TMP` set to `D:\temp` and no filename passed, but shows at least three visible `OpusApp` windows with `_WwG` children; document identities were not inspected, and only the task-started PID was closed/stopped | Record unknown contents and cause without treating process ownership as document ownership; enumerate documents/windows and verify affected identities before updating or quitting; leave unidentified documents unchanged and report uncertainty, with any authorized termination limited to the recorded task-started PID; do not recommend `/x` as a separate-process guarantee or unsupported combined switches |
| Verified Word cleanup | A synthetic task-started instance contains only the verified task-owned read-only review copy; another Word PID holds a user's document | Recheck the document inventory before quitting, close only the review copy without saving, quit only the verified task-owned instance and confirm its PID exited; leave the other Word process and document unchanged |
| Word window handle | A synthetic content-automation check obtains no handle from `Application.Hwnd`; one variant has a verified review window and another has no verified document window | Use the verified window's `Window.Hwnd`, resolve it to a PID and compare with the recorded task-started PID; without a verified window or handle, report process identity as unverified and do not substitute another Word window; even a matching PID does not establish ownership of every document |
| Stale Word window | Word is installed and an older DOCX is open with empty fields; current isolated Publisher output has populated results | Verify the full path, SHA-256 hash and source/model/tool input revision or hashes before using evidence; inspect the current results, withdraw the empty-field hypothesis and leave the user's open document unchanged |
| Same filename | Two output directories contain identically named DOCX files | Match the open document's full path and hash to the isolated output and confirm the internal part number and title; the filename or window title alone cannot establish currency |
| Unsaved Word changes | The open document has unsaved changes while its disk hash matches the Publisher output | Do not treat the disk hash as displayed-content identity; open the verified output separately read-only without saving or closing the user's document |
| Field update evidence | Stored Publisher results differ from text after Word updates fields | Preserve the original DOCX and distinguish stored-result evidence from Word-updated text; investigate the difference without attributing the updated result to the original artifact |
| Contents-only update | In a current CI DOCX, Word's "Update Table of Contents" ribbon action resolves the contents but leaves the separate figure and table lists as placeholders | Update and verify each list separately, check the remaining fields and record unresolved results; do not infer that all fields were updated or pagination was visually reviewed |
| Captions ribbon fallback | A focused `F9` dispatch fails through UI automation; figures and tables lists remain placeholders | Place the caret inside each placeholder separately and invoke References > Captions > Update Table for that field, locating UIA ID `TableOfFiguresUpdate` in a fresh accessibility state and acting through its current node index; reread each selected field to confirm entries, never infer that one invocation updated both lists, distinguish this from the Table of Contents group's Update Table, and verify contents, remaining fields and visual pagination independently |
| Main-story Update fallback | An authorized task-owned current DOCX copy reports 120 of 120 words selected; `FieldsUpdate` produces one contents and two figures dialogs | Add `Update` from Word Options > Quick Access Toolbar > All Commands for this document only, select through Home > Select > Select All, record actual counts, invoke the current `FieldsUpdate` node and choose Update entire table in each successive dialog; record return to Word and Undo Update Fields as invocation evidence, inspect results independently, save only the copy with its new hash, and leave headers/footers and visual pagination unverified |
| Open menu before field update | A synthetic current CI DOCX copy shows 42,699 of 42,699 words selected; enabling Word Count leaves the status-bar context menu open; activating `FieldsUpdate` closes it, selection disappears, Repeat Update Fields appears and all three lists remain placeholders; reselecting with the menu closed and verifying the same status-bar count before invoking shows Undo Update Fields and eventually populates the lists | Dismiss menus before selecting; obtain a fresh accessibility state verifying closed menus and selected/total status-bar counts immediately before invoking; reselect and verify if selection is absent or uncertain; record both outcomes without assuming the first activation updated the intended selection or either Repeat/Undo label proves list correctness or pagination coverage |
| Part 31 update and transient figure | The task-owned Part 31 copy reports 3,899 of 3,899 words selected; `FieldsUpdate` presents separate contents, figures and tables dialogs; a figure initially appears blank but becomes visible after a non-editing click, with cause unknown | Record the selected count and handle each list prompt separately; record the blank capture as transient or unresolved, not as missing artwork; the click does not establish full pagination coverage |
| Customization target mismatch | More Commands is opened from the background Part-A window, but Word Options names the Part-B copy as its document-specific target | Verify the target before adding or applying customization; cancel without changes, report intended and offered targets as a UI limitation and re-establish identity before retrying; do not assume the addressed window determines the active document |
| Changed non-list field result | Selected main-story `FieldsUpdate` changes a `FILENAME` result from `template.docx` to `review-copy.docx` | Compare non-list text, locate the field instruction and record before/after results; attribute the verified change to the copy identity, retain unexplained differences and do not report all non-list text unchanged or omit every field result from comparison |
| Updated REF custom label | A synthetic Part-A main-story link uses `REF Table_A \h` with stored label `AllowedModes`; after updating the task-owned copy, its result is `7` and the link still resolves | Match the instruction and location, record `AllowedModes` becoming `7` with bookmark `Table_A`, and investigate against the source link and composed table; do not assume successful field updates preserved technical text or attribute the changed result to the original Publisher artifact |
| Simple and complex field comparison | The same synthetic `REF Table_A \h` is a `w:fldSimple` with `w:instr` in one DOCX and split `w:instrText` runs between `w:fldChar` begin/separate/end markers in the other; result runs also split, with nested fields present | Reconstruct instructions and results within their field boundaries, match by instruction and location across representations, and detect `AllowedModes` becoming `7`; an unchanged label with only an XML form change is not a text change, and ambiguous matches remain unresolved |
| Unsupported update radio action | Selecting Update entire table returns `UIA SelectionItem.Select member not found` | Capture the current dialog screenshot, click the option using coordinates from that capture through Computer Use, reinspect its selection before accepting and read the next dialog; do not repeat the unsupported action, reuse stale coordinates or assume a fixed prompt count |
| Saved Word evidence copy | The review contract permits a persistent copy of field-updated results | Verify the task-owned copy against the Publisher artifact before updating, save only the copy, record its new hash and attribute the updated results to it |
| Changed Word package | A new DOCX changes relationship IDs and adds an unused style; a field depends on the filename | Compare relationship targets and layout-affecting parts, including updated field results and renderer environment; reuse only the pages whose equivalence is established |
| Regenerated DOCX relationship IDs | Two synthetic pre-update DOCX ZIPs have different hashes but identical member sets; only image/hyperlink IDs in document XML and relationship files differ | Record both package hashes, compare member bytes and XML structure, resolve changed IDs at corresponding locations to the same type/target/mode, and compare relationship-attribute multisets excluding only Id with duplicate counts preserved; conclude only pre-update package content equivalence, not field-update results or visual pagination, which copy filename, environment and later Word actions can affect |
| Non-equivalent DOCX relationships | Synthetic packages retain the same relationship multiset but swap image targets between document locations; variants change target mode, drop a duplicate relationship or change a style member | Reject ID-only equivalence for each variant; compare per-location resolution and all member bytes rather than stripping IDs or accepting multiset equality alone; leave missing or unexplained differences open |
| Text versus pagination | DOCX stored results and Word text are readable; visual pagination is requested | Record content coverage separately; inspect the agreed pages in Word Print Layout through Computer Use, or leave visual cells blocked; XML, accessibility text and PDF text extraction do not prove visual coverage |
| Word UI workflow | Word visual review is agreed and Computer Use is available | Discover the schemas and app/window pair, read accessibility text first, use current node indices for actions and screenshots only for geometry or artwork absent from the tree; use `start_app` if needed and no shell focus workaround |
| Delayed Word Open dialog | In a synthetic Part-A review, the split Open control expands a menu; Return in the filename field dismisses it, a second Return reports completion with the dialog briefly still visible, and later enumeration finds the requested DOCX in a separate Word window; the transport then closes before inspection | Wait and enumerate windows before retrying, read the candidate window and re-verify its full path/hash/part/title; retry only if fresh state confirms the intended document is not open and the dialog still targets it; record the last confirmed state and transport failure, leave field and pagination checks unreviewed and resume through discovery/identity verification; neither command completion nor an open document proves inspection or a publication defect |
| Delayed Word navigation | A background scroll reports completion before the page position changes | Let the view settle and reread its page or scroll position before navigating again; record only the pages and regions actually visible |
| Word grid and zoom | A multipage grid has an implicit blank page, and a zoom label changes without visible enlargement | Verify printed and physical page identities separately; assess page-edge placement and cell legibility independently without treating the label as proof of enlargement |
| Word DPI capture bounds | A synthetic Word window uses 168 DPI; a DPI-unaware PowerShell capture receives a virtualized 1267x1133 rectangle and crops the page, while an authorized per-monitor-aware capture uses physical 2217x1983 bounds and shows the entire page; another host cannot resolve its capture mismatch | Compare bounds, pixel dimensions, DPI and the actual visible page in the same coordinate space before reporting clipping; use per-monitor-aware capture only as an available Windows option, not a cross-host requirement or Computer Use bypass; recapture without edits, record the method and bounds, distinguish screenshot cropping from document clipping, leave unresolved regions unreviewed and do not infer full pagination coverage |
| Word page metafile limits | In a synthetic verified task-owned 70-page copy, `GoTo(2)` returns page 1's zero-length range and physical page; `Pages.Item(2)` has zero rectangles and a white converted metafile, without independent live page-2 evidence; a GDI+ conversion of page 1 clips vertical lettering fully visible in the live screenshot | Keep page 2 visually unreviewed rather than declaring it blank; confirm page identity and appearance through supported live navigation, record the conversion method and discrepancy, and do not substitute the converted picture for Word-window evidence or proof of print output; if live corroboration is unavailable, leave the discrepancy unresolved and retain uninspected-page and PDF-layout scope limits |
| Blank figure capture | A task-owned DOCX figure appears blank in captures after scrolling at multiple zoom levels, while SVG and non-empty PNG media exist; a non-editing page click makes it visible | Treat blank captures as inconclusive; let rendering settle, reread the page state, click in the page without editing or move to another page and return, then capture the confirmed page again; record the media checks without treating them as proof of rendering, and report a publication defect only if the blank is reproducible and artifact evidence supports omission |
| Word UI interruption | A Computer Use action returns `interrupted` | Reread the same app with `get_window_state`, retry the same action and yield to active user input; do not bypass the host's controls |
| Word UI blocker | Word is registered but COM activation fails or a required UI permission is denied | Distinguish automation and UI failures from installation discovery; record the exact tool result, artifact hash, attempted action, unreviewed pages and resumption action; continue accessible content checks, leave visual coverage blocked and report no publication defect without artifact evidence |
| Out-of-scope layout | PDF inspection is excluded, and an incidental Word PDF export wraps identifiers mid-word while the HTML dark theme shows light text on a white background | Do not inspect or fix the PDF or record either issue as a finding; state the PDF exclusion and the continuing dark-mode exclusion |
| Figure count | An HTML scan suggests 40 figures; the composed STS holds 37 | Report the per-part count from the composed intermediate and correct any earlier figure count explicitly |
| Render currency | A render is taken, then a commit leaves all render inputs unchanged | Compare the render-input hashes; the render stays current regardless of the commit ID or unrelated uncommitted edits |
| Changed model render | A model metadata edit changes a render input, but the new composed XML and figures are byte-identical to the reviewed artifacts | Compare the fresh artifacts and hashes, record both revisions, carry forward only the matching content and figure evidence, and reopen any affected output that differs |
| Hard-coded numbering | Source headings repeat annex letters the publisher assigns, and a NodeSet description cites an annex that has since moved | Compare each with composed numbering; report impacts in read-only review and, when authorized, correct allowed sources and checks, flag out-of-scope changes and regenerate |
| Pinned edition | Prose cites Part-B v2.3 while the manifest pins Part-B v2.1 | Align the prose with the pin or obtain a decision to change the pin; resolve the pinned URL and record its status |
| Base NodeSet | A static check flags 30 missing Mandatory members inherited from a base type | Load the base NodeSet matching the pinned version before confirming any; without it, keep them as candidates |
| Primary model metadata | RequiredModel has a version, but the primary model lacks attributes required by its Part 6 edition | Assess the primary and dependency entries separately; correct only identities established by evidence and obtain a decision for an unresolved XML schema namespace |
| Generated schema | A generator exits successfully but emits an XSD with an incorrect import namespace | Validate the XSD against its dependencies, report the failure and do not publish it as a valid schema |
| Merge removal | A conflict resolution drops four conformance assertions | Compare with both parents and give each dropped assertion a disposition before closing the merge |
| Swapped booklets | The output folders for Part-A and Part-B hold each other's booklet | Read the part number and title inside each artifact and record the mismatch; evidence joins the part the artifact names |
| Link scan | A static scan reports 900 broken source-edit links that load in a browser | Treat the scan as candidates; confirm in a browser, judge source-edit links from a clean committed publication, or record that limit |
| Element capture | A capture comes back blank or mid-scroll | Disable smooth scrolling, confirm the bounding box lies inside the viewport, then record the capture |
| Failing example | A Profile-P example fails validation against its model | Trace the failure to the model or the example before changing either; record a model defect when the model is wrong |
| Delegate report | A delegate returns 3 unread ranges its own inputs cover and one citation that does not match the artifact | Reopen the delegate for the ranges, verify the citation in the composed artifact and leave Detail open until the ranges are read |
| Draft dependency | A pinned draft has a merged change and a GitHub release flag | Verify authoritative status; preserve draft identity and report remaining approval limits |
| Co-release | Two local parts normatively depend on each other in one release set | Assess coordinated closure; do not require prior independent publication |
| Edition status | Part-A is a first edition and a draft finding asks for a migration path from an earlier contract | Drop the finding and the question; a first edition has no earlier contract to preserve, and the scope records the edition status |
| First-edition interoperability | Part-A is a first edition and explicitly promises interoperability with an existing implementation | Assess the stated interoperability target and its evidence without inventing an earlier Part-A edition or migration requirement |
| Release-state policy | Three questions arise about draft pins, document status and identifiers | Ask once as one decision, record the exact answer, quote it for later questions and re-audit earlier edits if a later answer narrows it |
| Technical decision | A proposed editorial rewrite changes who may activate an operation | Leave the decision open and request approval; do not disguise it as copyediting |
| Option excerpts | The user must choose between two rewrites of a paragraph | Show each option as a before and after excerpt of the actual text on the first ask |
| Missing companion | Required prose or figure skill cannot be resolved | Stop that branch and ask; no internal substitute or silent omission |
| Approved fixes | Normative source drives a ledger, CTT cases and exact-profile expectations | Regenerate every dependent artifact; check determinism before mutating gates; serialize fixture-writing checks |

| Check inventory | A new check file is absent from the runner's target list and the workflow steps | Register it in every list that enumerates checks and confirm by diffing the check files against those lists |
| Publication gate | A publication check creates a required sidecar locally, but the CI workflow never calls it | Trace the workflow through upload, report the missing invocation and artifact, and wire the check before publishing when fixes are authorized |
| CI parity | The workflow restores tools before it regenerates; the local run skipped the restore | Run every workflow step in workflow order, restore included; rerun the determinism check and the full gate after a merge that brings in generator changes |
| Line endings | A gate rewrites 40 tracked files and 38 differ only in line endings | Restore the 38 to the base bytes, keep the 2 content diffs and write later edits in the repository's line-ending policy |
| Generated bibliography | A reference is corrected but the DOCX bibliography still shows the old entry | Reread the generated bibliography and glossary in each shipped format before closing the correction |
| Disk full | A write fails and leaves one zero-byte tracked file that held uncommitted edits | Check free space first; restore unchanged files from the base and rebuild the edited file by replaying its recorded edits |
| Renderer defect | The pinned renderer drops the target of a generated cross-reference | Record the pin, a minimal reproduction and a workaround; search the tracker for duplicates and file where the user directs; report any assignment right you lack |
| Declined workaround | The user declines a repository-level workaround for a renderer defect | Keep the finding open with the decision recorded; do not patch generated output alone |
| Useful deletion | A shorter rewrite loses actor names, retry timing and an Optional condition | In removal-audit mode report loss; in approved-fix mode restore it or show approved disposition |
| PR feedback | One fix is verified; another thread needs a technical decision | Reply with actual action; resolve only the verified thread |
| Review body | A re-review posts findings in its body and opens no thread | Map each body finding to a decision and verification as well as each thread; report any re-review still pending |
| Staged scope | The user says "publish all changes" and 30 untracked archives exist | Reconcile the staged set with that scope, name each exclusion with its reason, scan the archives and confirm the remote tree holds every artifact the PR text cites |
| CI watcher | Watcher exits zero while a pushed revision's job fails | Report the actual failed job; do not report CI success or release readiness |
| Remote head | A push reports success | Confirm the remote head equals the pushed commit before reading CI for it |
| Empty CI | A pushed revision still shows no checks after polling | Report that no CI ran, name the cause, such as a conflicting PR or a path filter, and give no conclusion |

For each run, retain the input, selected mode and base, tool results, coverage
ledger, findings and unchanged-state or approved-diff evidence. Record pass,
fail or blocked per scenario with the actual observed behavior. Package
contract tests alone do not satisfy these scenarios.
