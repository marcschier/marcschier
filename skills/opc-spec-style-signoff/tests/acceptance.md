# Acceptance scenarios

Use a synthetic Publisher fixture or a repository whose review inputs and artifacts can be handled in the test environment. Do not upload repository content to exercise skill installation.

| Scenario | Expected behavior |
|---|---|
| Read-only approval request with current source, stale HTML and no Word artifact | Freeze current inputs and render in isolation. If an applicable format cannot be verified, report the gap and withhold a passing verdict. Leave the worktree and review comments untouched. |
| A policy ambiguity and a pure style violation in the same Method | Cite each passage and rule. Ask about the policy with a recommendation and a deferral choice. Preserve that policy until resolved; do not convert a preference into a required edit. |
| A guarantee moved out of a Method, with a repeated copy in a generated description and a CTT case | Verify the owner, preserve the guarantee and fix or cross-reference every dependent copy. Change the generator input if it owns the description. Re-render and inspect both formats and the packaged CTT copy. |
| A defect exists only in Word and no source change fixes it | Establish the exact Publisher defect. Without approved exception, do not pass. With narrowly scoped approval and no other departure, report PASS WITH EXCEPTIONS. |
| Independent reader finds a new issue in a changed dependent table | Record the new issue with the same evidence standard, rebuild after the approved fix, and recheck the affected surfaces. Carry earlier coverage forward only after verifying the delta. |
| Resume a NOT READY fix-mode draft with a fixed table, two runnable editorial fixes, a partial glossary check and a genuine policy blocker | Reconcile the last edition with the worktree. Complete both fixes, collect the missing glossary evidence, and recheck changed dependencies. Do not report the first successful build as completion. Ask about the policy without implying an exception; report it as the blocker only after the remaining runnable checks are complete. |
| A guide is intentionally source-only, while a promised CTT download is absent | Check the guide and its references in source and mark guide asset checks not applicable with delivery evidence. Keep the missing CTT asset in the closure queue. Neither infer a missing guide artifact nor waive the promised download. |
| A rule is verified in HTML but not in an in-scope Word artifact | Record separate subchecks with edition and locations. Keep the Word subcheck open, name the precise missing evidence and carry it into the closure queue. Do not convert a coverage fraction into a passing verdict. |
| A schema derived from a generated model is also embedded in that model | Check the complete regeneration chain, including the embedded copy. Do not freeze an intermediate model merely because the standalone schema validates. Freeze only when the expected outputs no longer change on regeneration. |
| Two Word rerenders assign different IDs to the same links; another rerender changes the destination of one link | Retain each raw file hash. Resolve the relationships and compare their types, modes and targets. Treat only the destination change as a link difference. |
| An HTML download resolves, but the standalone STS package is missing the same relative target | Resolve links from each documented delivery location. Keep the missing STS asset open even though the hosted download works. |
