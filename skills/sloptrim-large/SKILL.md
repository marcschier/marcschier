# Sloptrim for large files

1. **Confirm scope and mode.** Resolve the requested paths or globs to a list of files. Ask for any unset choices in one prompt: **Normal** (default, flag scores above 40) or **Strict** (flag scores above 20 and scrutinize character artifacts); **Review only** (default, no source changes) or **Editorial fixes** (edit selected files in place). An unanswered action never authorizes edits. Limit input to UTF-8 Markdown and plain text.
2. **Load Sloptrim.** Invoke the installed `sloptrim` skill once unless its context is already loaded. Resolve `scripts/detect.py` from that skill's installed directory, not the current repository. If either is unavailable, report the missing prerequisite and stop. Use its style, preservation, and self-audit rules; the selected action and coverage report are the outer workflow. Do not change global Sloptrim settings.
3. **Plan coverage.** For every file, run `python <skill-dir>/chunks.py <file> plan`. Record each chunk ID and original line range as pending. The plan includes the file's SHA-256 and partitions the entire document; ranges can share a line when a very long line must be split. For each ID in order, run `python <skill-dir>/chunks.py <file> scan <id> --detector <detect.py> --mode <normal|strict> --expect-sha <sha>` and `python <skill-dir>/chunks.py <file> read <id> --expect-sha <sha>`. Read the full authored prose, not only detector samples. If the tool truncates the output, add `--window <offset> <length>` to `read` and advance through the chunk until the entire range is accounted for. The plan marks fenced and generated spans by file-relative character offsets; the scanner omits those spans. Carry section and open-block context across boundaries.
4. **Review every chunk.** Read all authored prose and mark the range `reviewed: unchanged` or `reviewed: findings`, even when the score is below the threshold. Record actual findings with file, original line and suggested wording. Mark generated or verbatim ranges `protected` and explain why; don't call them reviewed prose. Preserve headings, anchors, tables, code, generated blocks, meaningful Unicode, terminology, citations, placeholders, and normative modals. Treat detector flags as leads, not instructions; recurring specification language can be appropriate.
5. **Deliver the chosen action.** For review only, present findings and coverage without changing files. For fixes, finish reviewing a file before editing it. Confirm the file still matches the planned SHA; if it changed, re-plan rather than applying stale edits. Edit only the reviewed prose that needs changes. Keep repository formatting, including one-line paragraphs where required. Re-plan and rescan edited files; inspect the character-scrub findings and the actual diff, and confirm the edits preserve facts and protected content. Use the detector's scrub as a diagnostic, not as a file replacement.
6. **Close the ledger.** Report the reviewed files, coverage through the last authored section, and any protected or unreviewed ranges. In review mode include actionable findings; in fix mode name what changed. Do not claim completion while any authored range is unread or any chunk is truncated. If the task spans turns, preserve the pending ranges and resume at the next unread chunk.
